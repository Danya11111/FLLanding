# Настройка с портами 3000 (фронт) и 3306 (БД)

## Важно понимать:

- **Порт 3000** — фронтенд приложение → нужен в nginx конфиге для проксирования
- **Порт 3306** — база данных MySQL/MariaDB → НЕ нужен в nginx, используется только между контейнерами

## Архитектура:

```
Internet
   ↓
nginx-proxy:80
   ↓
   ├─→ arhipovdan.ru → fllanding:80
   └─→ nikitintex.ru → gooddriveweb-app:3000 (фронтенд)
                        ↓
                   gooddriveweb-db:3306 (БД, только внутри сети)
```

## Что нужно сделать:

### 1. Проверьте имя контейнера фронтенда

```bash
docker ps
```

Найдите контейнер, который слушает порт 3000. Это ваш фронтенд контейнер.

### 2. Конфигурация nginx уже обновлена

Файл `nginx/conf.d/nikitintex.ru.conf` настроен на порт 3000:
```nginx
proxy_pass http://gooddriveweb-app:3000;
```

Если имя контейнера другое — замените `gooddriveweb-app` на правильное.

### 3. Подключите контейнеры к сети

#### 3.1. Фронтенд контейнер (порт 3000)

```bash
docker network connect fllanding_web-network gooddriveweb-app
```

#### 3.2. БД контейнер (порт 3306) - опционально

Если БД контейнер должен быть доступен из других контейнеров в этой сети:

```bash
# Узнайте имя БД контейнера
docker ps | grep 3306

# Подключите к сети (если нужно)
docker network connect fllanding_web-network <имя-бд-контейнера>
```

**Важно:** БД контейнер обычно уже подключен к сети вашего первого проекта. Если фронтенд контейнер может к нему подключаться — дополнительных действий не требуется.

### 4. Проверьте, что фронтенд контейнер слушает порт 3000

```bash
# Проверьте внутри контейнера
docker exec gooddriveweb-app netstat -tuln | grep 3000
# или
docker exec gooddriveweb-app ss -tuln | grep 3000
```

Должно показать, что порт 3000 слушается.

### 5. Проверьте переменные окружения фронтенда

Убедитесь, что фронтенд контейнер настроен правильно:
- Слушает на порту 3000 (не на 80)
- Может подключаться к БД по имени контейнера БД (если БД в другой сети)

### 6. Запустите деплой

```bash
./deploy.sh --compose
```

### 7. Проверка работы

```bash
# Тест локально
curl -H "Host: nikitintex.ru" http://localhost

# Должен вернуть HTML от вашего фронтенда на порту 3000
```

## Если БД в другой Docker сети

Если БД контейнер находится в другой сети (например, созданной другим docker-compose), есть два варианта:

### Вариант 1: Подключить БД контейнер к сети web-network

```bash
docker network connect fllanding_web-network <имя-бд-контейнера>
```

Тогда фронтенд сможет подключаться к БД по имени контейнера.

### Вариант 2: Использовать внешнюю сеть в docker-compose.yml

Если БД управляется другим docker-compose, можно подключить оба проекта к одной внешней сети:

```yaml
networks:
  web-network:
    driver: bridge
  external-db-network:  # сеть, где находится БД
    external: true
    name: <имя-сети-где-бд>
```

И в сервисе фронтенда указать обе сети.

## Проверка подключения к БД

Если фронтенд не может подключиться к БД:

1. Проверьте имя БД контейнера в переменных окружения фронтенда:
   ```bash
   docker inspect gooddriveweb-app | grep -A 20 "Env"
   ```

2. Проверьте, что БД контейнер доступен по имени:
   ```bash
   docker exec gooddriveweb-app ping <имя-бд-контейнера>
   ```

3. Проверьте порт БД:
   ```bash
   docker exec gooddriveweb-app telnet <имя-бд-контейнера> 3306
   ```

## Итоговая схема портов:

- **nginx-proxy**: 80 (внешний) → принимает все запросы
- **fllanding**: 80 (внутренний) → для arhipovdan.ru
- **gooddriveweb-app**: 3000 (внутренний) → для nikitintex.ru
- **gooddriveweb-db**: 3306 (внутренний) → только для связи с фронтендом

Никакие внутренние порты (3000, 3306) не пробрасываются наружу — они доступны только внутри Docker сети.
